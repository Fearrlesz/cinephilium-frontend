## 4.10.0 — отмена вайба и его видимость

**Дата: 03.11.2026.**

### Смысл

Вайб был «оценкой без выхода»: поставить можно, снять нельзя, а в технической
и комбинированной колонках он выглядел прочерком. Из-за этого в профиле и
списках оценивших vibe-only выглядел как отсутствие оценки, а лента писала
«сделал что-то с фильмом». Теперь вайб отменяется, а везде, где нет
вычисленного балла, показывается `вайб N` — без подмены technical/combined.

### Что изменено

- Backend `DELETE /api/ratings/:id`: только владелец и только vibe. Удаляет
  Rating, Action `rating`, Event `vibe`; отвязывает `Watch.ratingId`;
  `counters.vibes -1`, `totalPoints -2`; ответ `{deleted, filmId}`. Full →
  `400 FULL_RATING_CANNOT_BE_CANCELLED`, чужая/нет → `404`.
- `src/pages/FilmPage/hooks/useVibeRating.js` — `cancelVibe` с optimistic
  очисткой, DELETE, reload film/users, откатом и уведомлением.
- `RatingPanel` — кнопка «Отменить вайб» только для vibe-only; в technical и
  combined крупно `вайб N` с `/ 10` и подписью «не вычислен». `RatingContext` —
  «Ваш вайб» `N / 10`.
- `FilmPage` (модалка всех оценок), `UsersList`, `ProfileTabs`,
  `RatingDetailsModal` — `вайб N` вместо `—`; `scoring.js` — `formatVibe`.
- `ActivityFeed` — шаблон `vibe`: «поставил вайб … — N/10».
- `useActivityEvents` — `vibe` в списке допустимых типов.

### Проверка

Backend: `node --test tests/vibe-rating.test.js` → 17/17 pass (отмена,
full-запрет, чужая оценка). Frontend: production build `Compiled successfully`,
127.68 kB JS / 22.03 kB CSS. Mock API + Chrome CDP 11/11: лента, три колонки,
список оценивших, профиль, отмена, удаление события, 480 без overflow.
Скриншоты — `screenshots/vibe-cancel/`. Живой прод — `[UNVERIFIED]`.

- `src/App.js` — `key="login"` / `key="register"` у элементов маршрутов.
- `src/pages/FilmPage/components/CommentsSection/CommentsSection.jsx` — подпись

## 4.9 — каталог, глобальная навигация и плоский редизайн

**Дата: 03.11.2026.**

### Смысл

Сайт перестал быть набором отдельных страниц с разными шапками и «назад на
главную». Появился один публичный каркас: общий Header, редакционная главная и
отдельный каталог всей библиотеки. Каталог получил настоящие серверные фильтры,
поиск и сортировку, а импорт фильма теперь сразу открывает его страницу. Все
публичные разделы — главная, каталог, авторизация, профиль, топ, «О системе»,
приватность, контакты и админка — приведены к плоскому редакционному языку:
без неона, glass, тяжёлых теней, hover-подъёмов и декоративных анимаций.

### Что изменено

- `src/components/Header/Header.jsx` + `Header.css` — самостоятельный глобальный
  header: сам грузит `/auth/me`, сам разлогинивает, пункты Каталог/Архитектор/
  Топ/О системе, поиск, контакт, аватар/вход, мобильная панель.
- `src/components/SiteLayout/SiteLayout.jsx` — общий публичный layout с Header и
  `Outlet`; `App.js` переведён на вложенные маршруты. Auth-страницы — отдельный
  `AuthLayout`, админка — отдельный служебный layout.
- `src/pages/HomePage/HomePage.jsx` + `HomePage.css` — редакционная главная:
  заголовок, поиск, топ-5, «Новые в каталоге» (10), лента событий, CTA «Весь
  каталог». Полная сетка снята с главной. Импорт больше не пишет фронтовый
  `film_add` и сразу ведёт на `/film/:id` для нового и уже существующего фильма.
- `src/pages/CatalogPage/CatalogPage.jsx` + `CatalogPage.css` — новый `/catalog`:
  поиск, жанр, год, «с оценками/без», сортировка, активные чипы, сброс, сетка
  5/4/3/2, «Загрузить ещё», пусто/ошибка, TMDB-модалка добавления. Состояние — в
  URL: `?q=&genre=&yearFrom=&yearTo=&rated=&sort=&page=`; `focus=search`
  автофокусит поле.
- Backend `films.routes.js`: `GET /films` принимает `q` (экранированный regex по
  title), `genre`, `yearFrom/yearTo`, `rated`, `sort` (`title` добавлен);
  `pagination.total` считается после фильтров. Добавлен `GET /films/facets`
  (`genres[{value,count}]`, `years{min,max}`) до `/:id`.
- `src/components/AuthLayout/AuthLayout.jsx` + `.css` — общий каркас входа,
  регистрации, восстановления и сброса: две колонки на десктопе, одна на ≤860,
  подчёркнутые поля, azure-кнопка, inline-ошибки.
- `src/pages/ProfilePage/ProfileSettings.jsx` — inline-панель «Настройки»:
  `GET/PUT /users/me/privacy`, переключатели `hideProfile`/`hideFromFeed`,
  оптимистичное сохранение и откат. Свой скрытый профиль владелец видит, другие —
  stub без вкладок.
- Редизайн страниц: `AboutPage` (редакционная статья, блоки 01–05, пресеты,
  формула), `TopUsersPage` (таблица-лидерборд, top-3 azure, без медалей),

### Зафиксированные решения

- **4.9/6A** приватность — inline-панель в своём профиле через существующие

- **Расхождение:** отдельной страницы редактирования профиля по-прежнему нет;
  «Редактировать» заменено на «Настройки» приватности. `GET /films` и
  `/films/facets` расширены на бэкенде — без этого фильтры каталога были бы

## 4.7 — F7: комментарии к рецензиям

**Дата: 02.11.2026.**

### Смысл

Комментарий к рецензии — отдельный слой обсуждения текста, а не фильма.
Он не требует оценки: можно ответить автору, даже если фильм не оценён.
Блок живёт inline под каждой рецензией, свёрнут до «N комментариев», чтобы
страница фильма не разрасталась. Пре-модерация остаётся: сервер отдаёт approved
всем, а свои pending — автору; админ видит всё.

### Что изменено

- `CommentsSection.jsx` — пропсы `targetType` / `targetId`; режим фильма (F2)
  сохранён без изменений, режим рецензии грузит данные сам: счётчик через
  `limit=1` и `pagination.total`, страница по 5 корневых комментариев,
  «Загрузить ещё», форма под списком, ответы одного уровня, лайки, pending и
  пустое состояние.
- `ReviewsSection.jsx` — `<CommentsSection targetType="review" targetId={review._id} />`
  после оценки и спойлер-плашки каждой рецензии; F3-гейт и spoiler-логика не
  тронуты.
- `CommentsSection.css` — `.c-toggle`, `.c-thread`, `.c-more`, `.c-empty`,
  `.c-pending`, `.c-actions`, `.creplies`, `.citem--reply`, `.c-reply-note`;
  адаптив 620/480. Только токены, без новых hex/шрифтов/брейкпоинтов.
- Отдельная страница рецензии не создавалась: в коде её нет (`ReviewPage` —
  отсутствует), поэтому блок только inline на странице фильма.

### Зафиксированные решения

- **F7/1** — inline под каждой рецензией, отдельного маршрута нет.
- **F7/2** — свёрнуто до кнопки «N комментариев»; список и форма только после клика.
- **F7/3** — переиспользование `CommentsSection` пропсами; GET с `targetType` /
  `targetId`, POST с телом `{ targetType: 'review', targetId, text }`.
- **F7/4** — ответы одного уровня через `parentId`; у ответа нет кнопки «Ответить».
- **F7/5** — видимость pending определяет сервер; фронт ничего не фильтрует.
- **F7/6** — комментарий к рецензии не гейтится `userRating`.
- **Расхождение с контрактом:** в F2 у `CommentsSection` не было ни пагинации,
  ни ответов — они добавлены только в режиме рецензии; режим фильма остался
  прежним. `commentsCount` у рецензии нет, счётчик берётся из `pagination.total`.

## 4.1.1 — F1-fix: vibe-only не выдумывает combined

**Дата: 30.10.2026.**

### Смысл

На бэкенде vibe-only даёт `technicalScore: 0` и `combinedScore: 0` — это маркеры
«не вычислено», а не результат. F1 ошибочно доизобретал `combined = vibe × 10`

- `scoring.js`: `calculateCombined()` возвращает значение только при наличии и
  техники, и вайба; `yourCombined()` — только для `completeness: 'full'`.
- `RatingPanel.jsx`: для vibe-only combined `—`, без буквы, без формулы;
  мелкая мета «нужна полная оценка». Technical тоже `—`.
- `RatingContext.jsx`: «Ваша» — только full; delta считается только когда есть
  и «Сообщество», и «Ваша». Подпись «на основе вайба» удалена.
- `RatingSection.jsx`: «Ваша» берётся только из `yourCombined()`.
- `client.js`: одна строка — `errorCode` сохраняется до нормализации ошибки
  в строку. Поведение существующего UI не меняется.
- `useVibeRating.js`: `ALREADY_FULL_RATING` ловится по `errorCode`, текст оставлен
  запасным вариантом.
- `UsersList.jsx` и модалка «Все оценки» на странице фильма: для
  `completeness: 'vibe'` цифра `finalScore` не показывается (прочерк).
- `RatingSection.jsx` / `useVibeRating.js`: после сохранения vibe или full
  обновляется список `filmUsers` (`reloadUsers`), чтобы «Оценили фильм» и счётчик
  не отставали до перезагрузки страницы.

### Зафиксированные решения

- **F1-fix** — combined и technical только для full. Vibe-only: оба прочерка,
  никакого `vibe × 10` на фронте.

цифру, если в ответе есть `completeness: 'vibe'`. Правильный фикс — на бэкенде

## 1. API-клиент (`src/api/client.js`)

**Было:** один `token` в localStorage, без обновления, 401 → сразу редирект на `/login`.
**Стало:**

- `baseURL` из `REACT_APP_API_URL` (фолбэк — текущий onrender-адрес);
- `withCredentials: true` — иначе браузер не отправит HttpOnly refresh-cookie;
- access-токен в `accessToken`; дополнительно дублируется в старый ключ `token`,
  чтобы не переписывать 20 проверок в компонентах;
- на 401 — single-flight `POST /auth/refresh` и один ретрай исходного запроса;
  если refresh не удался — сессия чистится и пользователь уходит на `/login`;
- ошибки бэкенда `{ error: { code, message } }` нормализуются в строку, поэтому все
  существующие `err.response?.data?.error` продолжают работать;
- `logout()` отзывает сессию на сервере и только потом чистит локальное состояние.

## 2. Вход и регистрация (`src/pages/LoginPage.jsx`)

- Три состояния: `login`, `register`, `verify`.
- Логин сохраняет `accessToken` (раньше читал несуществующий `token`).
- Регистрация больше не ждёт токен: показывается экран ввода 6-значного кода из письма,
  кнопка «Отправить код ещё раз» вызывает `/auth/resend-verification`.
- Пароль — минимум 8 символов (синхронно с бэкендом).
- Два обязательных чекбокса: обработка персональных данных и cookie. Без них форма не уходит,
  а согласия отправляются в API вместе с регистрацией.

## 3. Сброс пароля

- `src/pages/ForgotPasswordPage.jsx` (`/forgot-password`) — email → `POST /auth/forgot-password`,
  всегда нейтральное сообщение об отправке.
- `src/pages/ResetPasswordPage.jsx` (`/reset-password?token=…`) — новый пароль + подтверждение,
  проверка длины и совпадения, отдельный экран для отсутствующего/битого токена.
- Ссылка «Забыли пароль?» на странице входа.

## 7. Деплой

На Vercel задать:

```
REACT_APP_API_URL=https://<бэкенд>/api
```

Домен фронтенда должен быть указан в `CORS_ORIGIN` и `CLIENT_URL` на бэкенде — иначе CORS
заблокирует запросы, а ссылка из письма «забыли пароль» приведёт не туда.
